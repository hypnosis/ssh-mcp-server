# CLAUDE.md — правила работы в ssh-mcp-server

MCP-сервер для работы с удалёнными серверами по SSH. Пакет опубликован в npm,
поэтому имена инструментов и формат профилей не ломаем.

Правила ниже выстраданы конкретными багами. У каждого написано, каким именно —
это не абстрактная дисциплина, а список мест, где мы уже обожглись.

---

## 1. Заявленная функция без живой проверки не сделана

**Откуда правило.** `pathSecurity` (ограничения на пути) числился готовым с коммита
«Sprint 2 & 3 завершены — Path Security»: код написан, README описывает, ROADMAP
отмечен ✅. На деле поле профиля не доезжало до конфигурации, валидатор не
создавался ни разу, защиты не было вовсе — ни для тильды, ни для абсолютных путей.
Прожило месяцы. Вскрылось за пять минут одним замером на контейнере.

- Функция считается сделанной, когда есть проверка на живом сервере, а не когда
  написан код и тест с моками.
- README и ROADMAP обновляются **после** живой проверки, не раньше.
- Новое поле профиля — обязателен тест на весь путь: файл профилей → загрузчик →
  сборка конфигурации → инструмент. Загрузчик собирает профиль вручную, поле за
  полем, и новое поле там теряется молча.

## 2. Каждый новый тест проверяется мутацией

**Откуда правило.** Сегодня мутация поймала не только чужие дыры, но и свежий
тест, написанный час назад: он не краснел, потому что мок отвечал хэшем на любой
путь, включая несуществующий.

- Сломать ожидание → убедиться, что тест красный → вернуть. Не покраснел — это не тест.
- **Мок должен быть злее сервера, а не добрее.** Мок и код пишет один человек с
  одной картиной мира и ошибается в обоих одинаково. Нет файла — мок обязан
  ответить «нет файла», а не хэшем.
- Руками это делается редко и забывается, поэтому есть `npm run mutate` — см. §9.
  Откат ручной мутации — **копией файла, не `git checkout`**: им сносятся
  собственные правки рядом.

## 3. Проверять на обоих контейнерах

Лаборатория: `mcp-alpine` (BusyBox) на 2231 и `mcp-debian` (coreutils) на 2232,
ключ `.lab/key`, поднять — `npm run lab:up`. При ручном ssh добавлять
`-o ControlPath=none`.

Наборы утилит расходятся, и расходятся молча:

- сторож времени убивает команду кодом 124 (coreutils) и 143 (BusyBox);
- `sha256sum` в coreutils экранирует имена с `\`, `\n`, `\r`, BusyBox — нет;
- длинных опций (`--quiet`) и манифеста на stdin у BusyBox нет.

Проверено на одном — значит не проверено.

## 4. Где в коде пара — тест на оба элемента

**Откуда правило.** Две дыры подряд: коды сторожа `[124, 143]` — тест был на
первый; два цикла в `collectRemoteHashes` — проверки покрыты только в первом.
Мутация «убрать 143» оставляла все 609 тестов зелёными.

Список, пара кодов, второй цикл, вторая ветка — каждый элемент под своим тестом.

## 5. Смена слоя, разбирающего данные, — это класс багов, а не один баг

**Откуда правило.** Переход с ssh2 на системный OpenSSH поменял ответ на вопрос
«кто разбирает путь»: SFTP отдавал путь протоколу, `scp` отдаёт его shell-у
сервера. Отсюда весь спринт ловили по одному: тильда, шаблон `*`, пробелы,
обратный слэш, перевод строки в имени, `$(...)`.

Меняешь транспорт или способ доставки — перепроверяй **всё семейство** сразу, а не
тот случай, на который пожаловались.

## 6. Не рассуждать там, где можно померить

Любое утверждение о поведении на сервере подтверждается замером на контейнерах.
Скрипты замеров держим в scratchpad, в репозиторий не кладём.

Так были опровергнуты и подтверждены: асимметрия имени `~weird.txt` (нет),
поведение `mv -T` на BusyBox (есть), потеря скачанного при тильде (есть).

## 7. Инварианты, которые нельзя ронять

- **Сохранность.** Целая копия существует в каждый момент времени. Данные пишутся
  рядом с целью под временным именем и встают на место одним переименованием.
  Обработчик ошибки никогда не трогает последнюю оставшуюся копию. Вся установка
  идёт через `src/managers/installer.ts` — частных путей замены не заводим.
- **Честный ответ.** Три исхода сверки не смешиваются: сошлось, не сошлось,
  проверить нечем. «Нечем» — это успех с пометкой, а не провал: иначе исправная
  передача на сервер без `sha256sum` выглядит как испорченная, и обработчик ошибки
  идёт удалять только что записанное.
- **Неполный ответ не выдаётся за полный.** Обрезка буфера, убитая сторожем
  команда — это «проверить нечем», а не расхождение. По расхождению установщик
  сносит уже уехавшее дерево.

## 8. Границы, которые не обсуждаются

- Имена инструментов и формат профилей не ломаем — пакет в npm.
- `fail2ban` на серверах не включать и не предлагать (он банит агента).
- Работающую функциональность не сужаем ради безопасности.
- Бэкенд ssh2 удаляется в CORE_10 (5.3) — его дефекты не чиним, фиксируем пометкой.

## 9. Сторожа, каждый на свой класс ошибок

**Откуда правило.** Все баги спринта нашлись руками и грепом. Разбор показал, что
они разной природы, и один инструмент их не закрывает:

| Что ловим | Кто звонит |
|---|---|
| мёртвый импорт, неиспользуемая переменная | флаги `noUnusedLocals` / `noUnusedParameters` |
| зелёный тест, который ничего не проверяет | `npm run mutate` |
| «забыл прогнать перед коммитом» | CI на всех ветках |
| невидимый знак, из-за которого поиск молча пуст | `tests/unit/source-hygiene.test.ts` |
| функция написана, но никуда не подключена | **никто из них** — только живой тест |

Последняя строка важнее остальных. `pathSecurity` мутации бы не поймали: юниты
мокают резолвер, и мутанты честно умирают в коде, который никто не вызывает.
Правило №1 инструментами не заменяется.

### Пустой ответ поиска — не доказательство

**Откуда правило.** В `openssh-runner.ts` жил настоящий байт `\0` — в коде писался
литерал из двух знаков, а в файл уезжал один байт. Из-за него `grep` считал файл
двоичным и молча ничего в нём не находил. Пустоту приняли за «такого кода нет» и я, и
два агента; одна запись в реестре долга утверждала прямо противоположное правде.

- Вывод «такого кода нет» делается только после проверки, что инструмент вообще видит
  файл: любой заведомо частый шаблон должен что-то найти в том же файле.
- Обёртки над `grep` в оболочке ведут себя иначе, чем системный: на спорном ответе
  повторить через `/usr/bin/grep`.
- Байт попадает в файл на границе передачи, а не по замыслу, поэтому правилом это не
  лечится — только сторожем из таблицы выше.

### Как пользоваться мутациями

```bash
npm run mutate              # всё, что ветка изменила относительно main
npm run mutate -- HEAD      # только незакоммиченное — прогон перед коммитом
```

- **Смотреть на выживших мутантов в свежем коде, а не на процент.** Балл по
  проекту бессмысленен, потому что мутации гоняют только юниты
  (`vitest.stryker.config.ts`): живым нужна лаборатория, и каждый мутант стоил бы
  отдельного прогона по SSH. Файлы, покрытые живыми тестами, выглядят хуже, чем есть.
- Выживший мутант в том, что дописал час назад, — это «тест недописан», иди чинить.
- Эквивалентные мутанты бывают (`new Array<T>(n)` → `new Array()` ничего не меняет).
  Отсеиваются глазами, за баллом не гонимся.
- Скорость: файл на 80 строк — 10 секунд, четыре файла — полторы минуты. Прогон по
  всей ветке идёт долго, поэтому по умолчанию мутируем только тронутое.
- Найденное, что не чиним сразу, — в `docs/tech-debt/`, не в голову.

### Чего сознательно НЕ ставим

- **Покрытие кода.** Не поймало бы ни одного бага спринта: пара `[124, 143]` —
  одна строка, исполняется целиком, покрытие 100% и зелёный отчёт ровно на дыре.
  Мутации отвечают на тот же вопрос честно.
- **ESLint.** Три пакета и конфиг ради того, что делают два флага компилятора.
- **knip как постоянный сторож.** Мёртвый экспорт прод не роняет. Прибраться
  разово — `npx knip`, без установки в проект.

## 10. Задание агенту: узко, с фактами, с правом ничего не менять

**Откуда правило.** Пять агентов приводили документы к факту. Двое честно ответили
«менять нечего», и это был верный ответ. Один приукрасил статус — написал, что снос
`ssh2` «в работе», хотя он не начат. Один оставил пустой пункт списка. Брак ловился
диффом за минуту, но только потому, что задания были узкими и проверяемыми.

- **Один агент — один файл.** Тогда правки не сталкиваются, а дифф читается целиком.
- **Установленные факты — в промпт.** Чего агент не знает, то он достроит: «`ssh2` ещё
  не удалён» приходится писать явно, иначе спишет его в удалённые по смыслу задачи.
- **Разрешить ответ «ничего менять не нужно».** Без этого агент найдёт себе работу.
  Формулировка «„всё сходится“ — нормальный ответ» экономит целый разбор.
- **Требовать доказательство `file:line`.** Проверяемое утверждение либо подтверждается
  за минуту, либо разваливается; пересказ своими словами не проверяется никак.
- **Верить диффу, а не отчёту.** Отчёт описывает намерение, дифф — результат.
- **Правило разведки класть прямо в промпт.** Агент не видит ни этот файл, ни хуки:
  без напоминания он идёт грепать дерево вместо семантического поиска.

## Как гонять

```bash
npx tsc --noEmit                      # типы + мёртвые объявления
npx vitest run tests/unit/            # юниты
npm run mutate -- HEAD                # мутации по незакоммиченному — перед коммитом
npm run lab:up                        # поднять лабораторию
SSH_MCP_LIVE=1 npx vitest run tests/live/   # живые тесты (без лаборатории падают, а не пропускаются)
```

Живые тесты убирают за собой сами. Если замер делался руками — проверить, что на
контейнерах не осталось следов (`~/.upload-*`, каталог с именем `~`, пробные файлы).
