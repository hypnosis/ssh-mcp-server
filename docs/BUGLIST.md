#### ✅ ISSUE-001: Тильда не раскрывается в путях файлов [ИСПРАВЛЕНО]
**Описание:** При использовании `ssh_file_read` с путями содержащими тильду (`~`), команда `cat` не может найти файл
**Статус:** ✅ ИСПРАВЛЕНО в v1.1.0 (Sprint 3 - 2025-01-15)
**Приоритет:** СРЕДНИЙ
**Воспроизведение (до исправления):**
```
ssh_file_read("~/.bashrc") → Error: cat: '~/.bashrc': No such file or directory
```
**Решение:**
Реализовано автоматическое раскрытие тильды через `$HOME`:
- `~/file` → `$HOME/file` → `cat "$HOME/file"` → shell раскрывает `$HOME` ✅
- `~user/file` → `~user/file` → shell раскрывает `~user` ✅
- Используются двойные кавычки для раскрытия `$HOME`
- Все остальные спецсимволы экранируются для безопасности

**Компоненты:** 
- `src/tools/file-tools.ts` - добавлены методы `expandRemoteTilde()`, `buildSafeCommand()`
- `src/tools/log-tools.ts` - добавлены методы `expandRemoteTilde()`, `buildSafePath()`

**Тестирование:**
- ✅ `ssh_file_read("~/.bashrc")` - работает
- ✅ `ssh_file_write("~/test.txt", "content")` - работает
- ✅ `ssh_log_tail("~/logs/app.log")` - работает
- ✅ Unit тесты добавлены в `tests/unit/path-security.test.ts`

**Дата исправления:** 2025-01-15
**Sprint:** Sprint 3 - Path Security & Tilde Expansion

## 🔴 АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ (ОБНАРУЖЕНО 2025-01-12)

### ARCH-001: Отсутствие пулинга SSH соединений 🔴 КРИТИЧНО
**Описание:** Каждая команда создаёт новое SSH соединение (Connect → Auth → Exec → Close)
**Влияние:** 
- 10 команд подряд = 10 полных циклов подключения = 15-20 секунд
- Должно быть: 1 соединение для всех команд = 2-3 секунды
**Производительность:** **6-10× медленнее** чем могло бы быть
**Компоненты:** `ssh-manager.ts`, `ssh-executor.ts`
**Статус:** 📋 ЗАПЛАНИРОВАНО (Sprint 2 - КРИТИЧНО)
**План исправления:** Sprint 2 (2025-01-13) - Connection Pool с keep-alive и auto-reconnect

### ARCH-002: executeBatch неэффективен 🔴 КРИТИЧНО
**Описание:** Batch команды выполняются последовательно, каждая с новым соединением
**Влияние:** 10 команд в batch = 10 соединений вместо 1
**Производительность:** **10× медленнее** для batch операций
**Компоненты:** `ssh-manager.ts:99-112`
**Статус:** 📋 ЗАПЛАНИРОВАНО (Sprint 2 - КРИТИЧНО)
**План исправления:** Sprint 2 (2025-01-13) - Использовать одно соединение из пула

### ARCH-003: Timeout race condition 🟡 ВАЖНО
**Описание:** Timeout handler может вызвать reject() после того как Promise уже resolved
**Влияние:** Редкие ошибки, двойной вызов resolve/reject
**Компоненты:** `ssh-manager.ts:86-89`
**Статус:** 📋 ЗАПЛАНИРОВАНО (Sprint 4)
**План исправления:** Sprint 4 (2025-01-16) - Флаг settled для предотвращения race condition

### ✅ ARCH-004: Неполное экранирование путей [ИСПРАВЛЕНО]
**Описание:** escapePath экранировал только single quotes, не все спецсимволы
**Влияние:** Потенциальные проблемы с путями содержащими спецсимволы
**Компоненты:** `file-tools.ts`, `log-tools.ts`
**Статус:** ✅ ИСПРАВЛЕНО в v1.1.0 (Sprint 3 - 2025-01-15)
**Решение:**
- Добавлены два метода экранирования:
  - `escapeForSingleQuotes()` - для обычных путей (безопаснее)
  - `escapeForDoubleQuotes()` - для путей с `$HOME` (экранирует `\`, `"`, `$`, `` ` ``, `!`)
- Стратегия: single quotes для обычных путей, double quotes только для `$HOME`
- Защита от injection атак (command substitution, variable expansion)
**Дата исправления:** 2025-01-15
**Sprint:** Sprint 3 - Path Security & Tilde Expansion

### ✅ ARCH-005: Нет валидации путей [ИСПРАВЛЕНО]
**Описание:** Отсутствовала whitelist/blacklist для путей, можно было читать любые файлы
**Влияние:** AI мог случайно читать чувствительные файлы (например `/etc/shadow`)
**Безопасность:** Не было ограничений на path traversal (`../`)
**Компоненты:** `file-tools.ts`, `log-tools.ts`, `path-validator.ts` (новый)
**Статус:** ✅ ИСПРАВЛЕНО в v1.1.0 (Sprint 3 - 2025-01-15)
**Решение:**
- Создан `PathValidator` с опциональной конфигурацией в профилях
- Поддержка `allowedPaths` (whitelist), `deniedPaths` (blacklist)
- Защита от path traversal (`allowTraversal: false`)
- Ограничение длины пути (`maxPathLength`)
- Интегрирован в `file-tools.ts` и `log-tools.ts`
**Конфигурация:** Опциональная, добавляется в SSH профили через `pathSecurity`
**Дата исправления:** 2025-01-15
**Sprint:** Sprint 3 - Path Security & Tilde Expansion

### ARCH-006: Profiles синглтон без reload 🟢 НИЗКИЙ
**Описание:** Профили загружаются один раз при старте, нельзя перезагрузить без рестарта
**Влияние:** Неудобство при разработке и изменении конфигурации
**Компоненты:** `profile-resolver.ts:81`
**Статус:** 📋 ЗАПЛАНИРОВАНО (Sprint 5)

### 📋 Для включения детальных логов:

**Важно:** Логи выводятся в stderr MCP сервера. Для просмотра логов нужно:
1. Открыть консоль/терминал где запущен Cursor
2. Или проверить логи MCP сервера в настройках Cursor

**Настройка в mcp.json:**
```json
{
  "mcpServers": {
    "ssh": {
      "command": "node",
      "args": ["/path/to/ssh-mcp-server/dist/index.js"],
      "env": {
        "SSH_PROFILES_FILE": "~/.cursor/ssh-profiles.json",
        "LOG_LEVEL": "debug"
      }
    }
  }
}
```

**После изменения mcp.json:**
1. Перезапустить Cursor полностью
2. Выполнить тестовую команду
3. Проверить логи в stderr (консоль Cursor или логи MCP)

**Что искать в логах:**
- `[Profiles File]` - загрузка профилей
- `[Profile Resolver]` - разрешение SSH конфигурации
- `[SSH Executor]` - детали подключения (ключ, путь, ошибки)
- `[SSH Executor] ❌` - ошибки подключения с деталями
