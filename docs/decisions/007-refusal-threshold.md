# 007. Где проходит граница между предупреждением и отказом

## Context

Отказ появился в проекте на одном классе команд — рекурсивном удалении в корень
(ADR-003). Дальше выяснилось, что тем же свойством обладают команды, ничего не
удаляющие с диска: `reboot` рвёт канал и уносит сессию, `docker compose down -v`
сносит том вместе с базой, `crontab -r` стирает весь список заданий одной буквой.
Все они печатали `⚠️ DANGEROUS COMMAND` и уходили на сервер.

Нужен был признак, по которому решают, а не список случаев. Попытка считать
частоту команды («редкая — блокируем») не проверяется: спорить о том, часто ли
администратор делает `DROP TABLE`, можно бесконечно.

## Decision

**Отказ, когда потеря окончательна. Предупреждение, когда потерю можно вернуть.**
Проверяемых признаков два, и достаточно любого.

**Проверка 1. Уничтожается сосуд целиком** — машина, база, том, диск, набор
заданий, системное дерево. Не содержимое сосуда, а он сам.

| Сосуд — отказ | Содержимое — предупреждение |
|---|---|
| `DROP DATABASE`, `dropdb` | `DROP TABLE`, `TRUNCATE`, `DELETE FROM` |
| `docker volume rm`, `docker compose down -v` | `docker rm -f`, `docker system prune -a` |
| `crontab -r` | правка отдельного задания |
| `mkfs`, `wipefs -a`, `lvremove`, `zfs destroy` | `chmod 777` |
| `reboot`, `shutdown`, `halt`, `poweroff` | `git reset --hard` |

**Проверка 2. Объект читают после того, как его уничтожили** в той же команде.
Правильный порядок — копия, перенос, удаление — уничтожение держит последним.
Сломанный (`rm -rf A && cp -r A A.bak`) читает то, чего уже нет, и вторая половина
цепочки работает вхолостую.

Общий инвариант, из которого следуют обе проверки: **уничтожение объекта — последняя
операция над ним. После неё объект можно создать заново, но нельзя прочитать.**

**Разбор ролей — одна позиция, а не грамматика команды.** Приёмник по умолчанию
последний аргумент; исключения названы поимённо: `-t`/`--target-directory` у копий,
`of=` у `dd`, ключ `f` у `tar`, первый аргумент у `zip`. Осмотр (`ls`, `test`, `stat`)
чтением не считается — так проверяют, что удаление прошло.

Маркер снятия один на все отказы — `# CONFIRMED-DESTRUCTIVE`.

## Alternatives

**Таблица ролей на каждую утилиту** (что у неё источник, что приёмник, сколько их).
Отвергнута: описывает команду целиком, на утилите вне таблицы не работает вовсе, а
покрытия сверх правила об одной позиции не даёт — обе конструкции одинаково слепы к
приёмнику посередине без флага.

**Второй маркер для остановки машины.** Отвергнут: маркеров становится столько же,
сколько классов опасности, и агенту приходится угадывать нужный.

**Блокировать `DROP TABLE` вместе с `DROP DATABASE`.** Отвергнуто: таблица
восстанавливается из дампа базы, база из ничего не восстанавливается. Порог должен
резать по этому свойству, иначе он режет по громкости слова.

**Помнить уничтоженное между вызовами.** Отвергнуто: память разошлась бы с сервером,
где путь могли пересоздать мимо нас, и сторож начал бы отказывать по своей выдумке.

## Consequences

- Разбор живёт в чистом модуле без сети (`src/utils/irreversible-command.ts`), врезка —
  первой в `refuseDestructive`: она не касается путей, поэтому ранняя ветка по целям
  удаления пропустила бы её мимо вместе с командой.
- Это **ломающее** изменение: автоматизация, зовущая `reboot` или `docker compose down -v`
  через MCP, теперь требует маркера. Перезагрузка роутера, закрытого хуком
  `router-no-reboot.sh`, требует **двух** маркеров в одной команде — они принадлежат
  разным системам и объединению не подлежат.
- Часть команд уехала из предупреждений в отказы, и старые тексты предупреждений для них
  больше не печатаются.
- Границы разбора признаны и записаны в README: удаление и чтение разными вызовами;
  единственный аргумент, сочтённый приёмником (`pg_restore dump.sql`); длинная форма
  ключа архиватора (`tar --file X`); утилита с приёмником посередине без флага.
- Проверено живьём на обоих контейнерах: сломанный порядок отказан трижды подряд, данные
  после этого читаются целыми; правильный порядок, проверка результата `ls` и
  пересоздание архива проходят молча.
