## История: версии v1.0.0 – v1.2.2

С 2025-01-13 по 2026-01-12 вышли версии v1.0.0 → v1.2.2: пять спринтов и один багфикс

v2.0.0 один транспорт: системный `ssh` с ControlMaster.

Планы и результаты тех спринтов — в `docs/sprints/archive/`: `CORE_02_connection_pool.md`,
`FIX_03_path_security.md`, `FIX_04_timeout_errors.md`, `CORE_05_profiles_monitoring.md`,
`FIX_06_metrics_fix.md`, `SPRINT_2_SUMMARY.md`.

## Подробности по спринтам v2.0.0

### CORE_08: транспорт на OpenSSH, современный MCP, интерактив ✅ ЗАКРЫТ
**Дата заведения:** 2026-08-02
**Файл:** `docs/sprints/planned/CORE_08_openssh_transport.md`
**Приоритет:** 🔴 КРИТИЧЕСКИЙ
**Целевая версия:** v2.0.0

**Проблема:** каждый вызов инструмента открывал новое SSH-подключение — fail2ban
на серверах видит поток аутентификаций и банит. Внутрипроцессный пул помочь не может:
stdio означает отдельный процесс сервера на каждое окно клиента.

**Решение:** отказаться от самописного пула в пользу штатного ControlMaster из OpenSSH.
Он мультиплексирует соединения между процессами, а не внутри одного.

- Спринт 1 — транспорт на системный `ssh` с мультиплексированием (шаги 1–7 сделаны:
  флип дефолта и снос `ssh2` закрыты в CORE_11)
- Спринт 2 — миграция MCP SDK 0.6.1 → 1.30.0 ✅ сделан: версия поднята, MCP-слой закрыт
  контрактными тестами, отказ несёт `isError` и вывод убитой команды, аудит отдаёт разбор
  ответа отдельным полем, отмена доведена до транспорта. Команду на сервере отмена не
  снимает — названо ограничением релиза (TD-08)
- Спринт 3 — интерактивный режим и detach-джобы, вынесен в отдельные спринты:
  [CORE_13](planned/CORE_13_detach_jobs.md) (сделан) и [CORE_14](planned/CORE_14_interactive_mode.md) (запланирован)

### CORE_09: сохранность данных и честность результата ✅ ЗАКРЫТ
**Дата:** 2026-08-03
**Файл:** `docs/sprints/planned/CORE_09_transport_safety.md`

Данные больше не могут молча исчезнуть и не могут молча испортиться. `rm -rf` по боевому
пути удалён, любое появление файла или каталога на месте идёт через единую точку установки,
содержимое файла не проходит через shell. 349 тестов → 461. Решение —
`docs/decisions/001-single-install-point.md`.

### CORE_10: безопасность подстановки, сетка бэкендов и флип ✅ ЗАКРЫТ
**Дата заведения:** 2026-08-03
**Файл:** `docs/sprints/planned/CORE_10_backend_parity.md`
**Приоритет:** 🔴 КРИТИЧЕСКИЙ
**Целевая версия:** v2.0.0

Три вещи, без которых нельзя переключать дефолтный бэкенд: значение параметра инструмента
исполняется на сервере; передачу файлов не проверяет ни один тест; пределы, часть которых
выстрелит ровно в момент флипа. Сам флип и удаление `ssh2` (шаги 6–7 спринта 8) доведены
в CORE_11: флип сделан 2026-08-05, снос — 2026-08-05 там же.

**Этап 1 закрыт (2026-08-03).** Значение параметра больше не исполняется на сервере:
восемь мест в четырёх файлах закрыты одним ограждением. Раскрытие `~` сведено к одному
способу — по домашнему каталогу из паспорта.

**Этап 2 закрыт (2026-08-04).** Появилась живая сетка передачи: один набор утверждений
против настоящих ssh/scp и ssh2 на BusyBox и на coreutils, результат сверяется манифестом
дерева. Лаборатория поднимается одной командой и живёт в репозитории; без неё `npm test`
пропускает сетку с предупреждением, а `npm run test:live` падает.

Сетка сразу нашла то, чего не видел ни один тест: старый бэкенд терял исполняемый бит и
пустые каталоги, а обход дерева не замечал символических ссылок — после флипа ответ
инструмента разошёлся бы с тем, что уехало. Из пяти пунктов этапа код потребовался в
двух; три отпали после замеров. 461 тест → 595.

**Этап 3 закрыт (2026-08-04).** Сняты пределы, которые ломали большие передачи: потолка
в 300 секунд больше нет (его ставит вызывающий), сверка хешей и уборка перестали жить под
чужими тридцатью секундами, дерево из тысячи файлов больше не упирается в дескрипторы.
Закрыт класс «имя вернулось не таким»: обратный слэш, перевод строки, шаблон, пробелы,
`$(…)` и тильда — шесть костюмов одного дефекта, каждый ронял данные или объявлял
расхождение на целых файлах. Правила путей из профиля наконец действуют: поле
`pathSecurity` не доезжало до инструмента ни разу с момента появления. 595 тестов → 631
юнит и 93 живых.

**Этап 4 закрыт (2026-08-05).** Живой замер настоящих инструментов на обоих контейнерах:
21 сценарий из 22 типовых доезжает верно, порчи содержимого нет. Настоящая причина жалоб
была не в данных, а в ответе на неверную форму вызова — отсутствующий параметр давал
внутренний сбой вместо понятного отказа, `files: []` отвечал успехом на невыполненную
работу. Теперь форма проверяется до первой команды. Заодно поймано: `concurrency` у
`ssh_upload`/`ssh_download` не работал никогда, хотя описание обещало обратное — помечен
как игнорируемый. 631 → 698 тестов.

**Смоук на боевых серверах пройден дважды, спринт закрыт.** Удаление `ssh2` и документация
под OpenSSH — в CORE_11 (закрыт). Дальше — CORE_12: приведение документации к факту и
выпуск v2.0.0, спринт в работе прямо сейчас.

**С чем выходим (2026-08-14).** Технический долг закрыт, кроме двух названных ограничений
— они входят в релиз осознанно и описаны в CHANGELOG. Признак провала в ответе и
потерянный вывод убитой команды закрыты спринтом 2 CORE_08
([TD-03](../tech-debt/archive/tool-schemas_03.md)).

- отмена не доведена от вызова инструмента до транспорта: долгую операцию нечем прервать
  снаружи ([TD-08](../tech-debt/cancellation-not-wired_08.md));
- проверка точки монтирования умеет читать `stat` в синтаксисе GNU и BusyBox; на сервере
  с другим она честно говорит, что не сработала ([TD-09](../tech-debt/mountpoint-check-bsd_09.md)).

### Отклонённые решения

- **Streamable HTTP + OAuth на VPS.** Рассмотрен как «современный подход к remote MCP»
  и отклонён 2026-08-02. Спека 2025-11-25 предназначает Streamable HTTP для серверов,
  живущих по URL; наш сервер локальный, а вынос его на VPS означал бы одну машину
  с ключами ко всему парку, доступную из интернета. Цена не покрывает выгоду.
  Пересмотреть, если понадобится доступ с нескольких устройств.
- **Ремонт существующего пула на ssh2.** Восемь дефектов почините — потолок останется:
  пул живёт внутри процесса.
- **Второй бэкенд на ssh2 ради мультиплексирования на Windows.** Там его нет на уровне
  ОС; деградируем до одиночных соединений, двойную поддержку не тянем.

### Присутствие снаружи: реестр и каталоги

**Официальный реестр MCP — сделано 2026-08-18.** Запись `io.github.hypnosis/ssh-mcp-server`
живёт в `registry.modelcontextprotocol.io`, версия 2.0.3 помечена последней. Описание
сервера собрано в `server.json`, право на имя доказывается полем `mcpName` в `package.json`,
публикация идёт из релизного прогона входом по `github-oidc` — секрета для неё не заведено.
Реестр держит только метаданные: сам пакет остаётся на npm.

Витрины поверх реестра (Glama, mcp.so, PulseMCP) подтягивают записи оттуда сами. Что
требует отдельной подачи и пока не сделано:

- 🔹 `awesome-mcp-servers` — пул-реквест со строкой в список
- 🔹 Smithery — свой `smithery.yaml`
- 🔹 Docker MCP Catalog — образ и их сканер
- 🔹 Иконка сервера в `server.json` — без неё мы в списках безымянная строка. Иконки
  инструментов и промптов протокол тоже принимает уже сейчас, версия SDK не мешает
- 🔹 Расширение для Claude Desktop (MCPB) — единственный путь в каталог Claude для
  локального сервера: Connectors принимают только удалённые, а удалённым наш быть не
  должен — это означало бы чужой сервис с ключами ко всему парку
