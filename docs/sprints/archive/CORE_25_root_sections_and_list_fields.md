## С чего начали

Два долга из контрольного круга CORE_24. Первый: аудит честно говорит «правила экрана
прочитать не дали», но снять этот отказ внутри самого инструмента нечем — и агент уходит в
`ssh_exec sudo`, то есть туда, откуда весь набор уводит. Второй: `ssh_file_list` обещан
описанием как список с размером, правами и владельцем, а отвечает выводом `ls` — схемы
ответа у него нет вовсе.

## Экран: права, которые уже были, и ложь, которой не ждали

Разбор кода дал больше самой жалобы. `sudo` в `ssh_audit_baseline` вешается на весь
прогон, а включался он условием «просили раздел `ssh`». Отсюда две вещи сразу:

- при наборе по умолчанию флаг **уже** читал правила под root — но нигде об этом не
  сказано, и [ADR-009](../../decisions/009-how-an-agent-reads-the-surface.md) утверждал
  прямо обратное;
- набор из одного экрана (`include: ["firewall"]`) с флагом уходил **без** `sudo` — ровно
  там, где его и просили.

Стало: флаг поднимает прогон, если запрошена любая секция, которой нужен root
(`SUDO_SECTIONS`), а его описание называет обе — `sshd -T` и правила экрана.

**Отказ по правам теперь говорит, чем его снять.** Без флага: «run with
`include_sudo_sections: true`». С флагом: «not readable even as root» — совет повторить с
правами был бы кругом.

**Молчали ещё двое.** Политика цепочки `INPUT` и правила `nat`, которые не дали прочитать,
не попадали в ответ никак. Непрочитанный `nat` при этом оставлял стоять утверждение
«докер мимо экрана ничего не публикует», которого никто не мерил. Теперь оба названы.

### Находка живого теста: экран есть, а ответ говорит «нет»

Юниты этого не видели, потому что подают заготовленный текст. Замер на debian под обычным
пользователем:

```
PATH=/usr/local/bin:/usr/bin:/bin:/usr/games
ufw       -- NOT FOUND (real: /sbin/ufw)
iptables  -- NOT FOUND (real: /sbin/iptables)
```

По SSH обычному пользователю не достаётся ни `/usr/sbin`, ни `/sbin`. Проверка
`command -v ufw` не находит установленный `ufw`, и аудит отвечает `not_installed` — «экрана
нет вовсе». Дальше по цепочке машина с включённым экраном получает предупреждение «no
firewall … incoming traffic is not filtered». Это не «не проверили», это утверждение с
обратным знаком.

На alpine расхождения нет: там `sbin` в `PATH` у всех — правило «проверено на одном значит
не проверено» сработало буквально.

**Стало:** команда аудита начинается с `PATH="$PATH:/usr/sbin:/sbin"`. Инструмент теперь
находится, отказ по правам называется отказом, и его снимает тот же флаг.

### Чем проверено

- Юниты: три ветки поднятия прав (только `firewall`, только `ssh`, оба), раздел без нужды
  в root, отсутствие просьбы; обе формы отказа; маркер с пробелами вокруг; префикс `PATH`;
  разделитель между командами секций.
- Мутации по тронутому коду: 11 мутантов, 0 выживших.
- Живьём на обоих контейнерах, под пользователем `deploy`: без флага правила закрыты и
  названы, с флагом — прочитаны; `ufw` на debian проходит путь `no_access → read`, на
  alpine остаётся `not_installed`, и «нет» не выдаётся за «молчит».

Лаборатория для этого получила `--cap-add=NET_ADMIN --cap-add=NET_RAW` и сами утилиты:
без прав на сеть даже root не читает правила, и ветка «прочитали под sudo» непроверяема.

## Список файлов полями

`ls` убран из инструмента целиком. Причина не в стиле: его вывод — это верстка, а не
данные. Размер округлён (`1.2K`), год печатается только у старых файлов, колонки
расходятся между BusyBox и coreutils, а имя с переводом строки становится двумя строками
таблицы. Разбирать это пришлось бы тому самому агенту, ради которого инструменты и заведены.

**Стало:** обход делает `find`, поля печатает `stat` в постоянном порядке, а имя стоит
последним — всё до него имеет твёрдую форму. Решение записано в
[ADR-011](../../decisions/011-directory-read-by-stat-not-ls.md), граница «где заводится
схема ответа» — в [ADR-008](../../decisions/008-answer-shape-and-legend.md). Записи режутся по маркеру, а не по строкам,
поэтому перевод строки внутри имени остаётся внутри имени.

```
LC_ALL=C find <путь> -mindepth 1 [-maxdepth 1] [-name <шаблон>] \
  -exec stat -c '__SSH_MCP_LS__%s|%Y|%U|%G|%a|%F|%d:%i|%n' {} +
```

Второй проход берёт цели ссылок, и берёт их **против пары «устройство:инода»**, а не
против имени: ключ переводов строки не носит, а имя носит. Одна закрытая дверь на двух
проходах даёт две одинаковые жалобы — они схлопываются в одну.

Замерено на обоих контейнерах перед тем, как писать код: `stat -c` с `%s %Y %U %G %a %F
%d %i %n` понимают оба, `find` знает `-mindepth`, `-maxdepth` и `-exec … +` — а вот
`find -printf` есть только у GNU, и `readlink` у BusyBox берёт ровно один аргумент.
Отсюда и форма команды.

**Что теперь в ответе:** `entries[]` с `name` (относительно запрошенного каталога),
`type`, `size` в байтах, `mode` восьмеричным, `owner`, `group`, `mtime` числом и `target`
у ссылки; отдельно `unreadable` — двери, за которые не пустили, и `truncated`.

**Отказ и отсутствие разведены.** Отказ на самом запрошенном каталоге — это провал вызова
с текстом сервера. Отказ внутри обхода — это ответ с названной дырой: остальные записи
собраны, а список, короткий ровно на интересное, не выдаётся за полный. Разбор жалобы
опирается на её текст, поэтому команда идёт под `LC_ALL=C`.

**Шаблон сменил хозяина.** Раньше `*.log` раскрывала оболочка сервера, и защитой служило
экранирование обратным слэшем; теперь шаблон едет закавыченным значением `-name`, а
разбирает его сам `find`. Следствия: `-la` больше не отказ, а шаблон; шаблон без
совпадений — пустой список, а не ошибка команды.

### Чем проверено

- Юниты: разбор имени с переводом строки, с `|` и с кавычкой; ссылка с целью и без;
  шесть слов `%F` из двух наборов утилит; сортировка; обрывок записи; дубль жалобы; обе
  формы жалобы (`coreutils` кавычит путь, BusyBox нет); пустой шаблон; обрезка.
- Живьём на обоих контейнерах, семь неудобных имён сразу: поля совпадают с тем, что
  положили, вложенное названо относительно каталога, ссылка приходит с целью, закрытый
  каталог назван и читается под `sudo`, несуществующий — отказ с текстом сервера.

## Хвосты

- Мутант `.join('; ')` → `.join("")` в сборке команды жил и до спринта: склеенные без
  разделителя команды юниты не замечали. Закрыт сторожем на разделители.
