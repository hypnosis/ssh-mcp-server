# CORE_27 — слепой удар останавливается показом цели

**Статус:** ✅ закрыт 2026-08-24
**Дата заведения:** 2026-08-24
**Ветка:** `feat/blind-target-guard` (от `main`)
**Решение:** [ADR-014](../../decisions/014-blind-target-is-shown-not-guessed.md)
**Происхождение:** разбор случая на боевой машине — сервис остановлен ударом по цели,
которую никто не назвал

---

## Зачем этот спринт

Сторож умеет отказывать там, где данные уносит навсегда, и там, где машина перестаёт
отвечать. Остановка сервиса в его область не входит — так решено сознательно.

Случай показал, что граница проведена не по тому признаку. Опасна не остановка: опасна
остановка того, чего никто не назвал. Агент отправил удар по цели, вычисляемой
подстановкой, будучи уверен, что бьёт по тестовому. Маска промахнулась мимо боевого
контейнера — тот уцелел случайно. Второй удар в той же строке, по шаблону командной
строки, попал в работающий процесс с пользователями.

Разрыв был не между «можно» и «нельзя», а между тем, что агент думал, и тем, что стояло
за подстановкой. Этот разрыв виден серверу и не виден агенту — значит его можно показать
до удара, а не после.

Прогон текущих сторожей (`npx tsx`, реальные функции, не по памяти):

```
   тихо  docker kill $(docker ps -q --filter ancestor=<образ>)
   тихо  kill $(pgrep -f '<шаблон>')
   тихо  pkill -f '<шаблон>'
   тихо  docker stop $(docker ps -q)
   тихо  systemctl stop <юнит>
   блок  docker compose down -v
   блок  reboot
```

## Что делаем

### 1. Распознать слепую цель — по тексту, без сети

Новый модуль рядом с существующими разборщиками. Чистые функции, ноль обращений к серверу.

Глаголы: остановка и снятие контейнера, снятие процесса, остановка юнита.
Признак слепоты в позиции цели: подстановка, обратные кавычки, переменная, глоб. Плюс
поиск процесса по образцу командной строки — там цель раскрываемая всегда, без всяких
скобок.

Литеральная цель не трогается: имя, идентификатор, юнит проходят молча.

**Проверка:** литеральные формы молчат, слепые ловятся, и ловятся обе половины склеенной
строки, а не только первая (правило про пару из CLAUDE.md §4).

### 2. Показать, что стояло за подстановкой

Раскрытие выполняется на сервере одним вызовом, результат не бьёт, а описывается: имя,
сколько живёт, слушает ли порт, есть ли установленные соединения. Для процесса — то же
плюс командная строка целиком.

Третий исход обязателен: посмотреть нечем (нет утилиты, ответ обрезан, сторож времени
снял команду) — это отказ, а не разрешение. Инвариант из CLAUDE.md §7 действует здесь без
послаблений.

**Проверка:** на обоих контейнерах, включая машину, где нужной утилиты нет — ответ должен
называть отсутствие, а не выдавать пустоту за «целей нет».

### 3. Отказ, который показывает и диктует форму

Текст отказа несёт список того, что попало бы под удар, и форму подтверждения с именами
из этого списка. Общего маркера в тексте нет: он не должен выглядеть выходом по умолчанию.

**Проверка:** сторож на сам текст — как в `tests/unit/tool-result.test.ts`: список
присутствует, имена совпадают с раскрытыми, общий маркер не предлагается.

### 4. Принять подтверждение — и не принять повтор

Подтверждение — маркер, несущий имена. Проверяется, что имена в маркере совпадают с тем,
по чему бьёт команда.

Повтор строки с нераскрытой целью блокируется всегда, независимо от маркера: пауза,
которую проходят повторной отправкой, — это не пауза.

**Проверка:** мутацией. Убрать сверку имён — тест обязан покраснеть; принять старую форму
с маркером — тоже.

### 5. Живая проверка

Оба контейнера, `npm run lab:up`. Функция считается сделанной после живого прогона, а не
после зелёных юнитов (CLAUDE.md §1). Наборы утилит расходятся молча — проверено на одном
значит не проверено (§3).

Лаборатория пользуется слепыми формами в собственных живых тестах — их придётся привести
к новому порядку, и это часть работы, а не помеха.

## Границы спринта

- **Литеральная остановка боевого сервиса проходит молча.** Сохранённая граница, а не
  забытый случай: сторож лечит слепоту, а не самоуверенность.
- **Прицел не судим.** Агент, увидевший список и решивший бить, действует осознанно.
- **Потеря канала — другой класс.** Сброс правил экрана, выключение фильтра в эту работу
  не входят.
- **Обход мимо `ssh_exec`** — запись конфигурации с последующим законным перезапуском —
  вне точки врезки и вне спринта.

## Открытые вопросы

1. ~~**Семантика списка команд.**~~ **Решено 2026-08-24: не трогаем, и в отказе о ней не
   говорим.** Совет «разрежь строку на список» проблему не решает — агент соберёт массив,
   и слепота останется той же. Отказ говорит только о цели.

   Отсюда же форма подтверждения: маркер несёт имена, а сторож **раскрывает цель заново и
   сверяет** с тем, что названо. Названо одно, под удар попало другое — отказ. Слепого
   пятна не остаётся и у подтверждённого удара.
2. **Проверка живости цели для литеральных ударов.** Единственный механизм, различающий
   боевой сервис в каталоге с тестовым именем, — смотреть на установленные соединения.
   Стоит один поход на сервер и обязательный третий исход. Отдельным решением, не здесь.

## Что сделано

- `src/utils/blind-target.ts` — распознаёт удар, чью цель раскрывает сервер, и отдаёт пробу:
  команду, которая назовёт цель, не трогая её. Ноль обращений к машине.
- `src/utils/strike-preview-parse.ts`, `src/managers/strike-preview.ts` — один вопрос машине
  и разбор ответа: контейнер по листингу движка, процесс по `/proc`.
- `src/utils/strike-refusal.ts` — текст отказа со списком целей, разбор подтверждения,
  сверка имён с тем, что удар достаёт.
- `src/tools/exec-tool.ts` — врезка в ту же точку, где стоят остальные сторожа, до отправки
  первой команды. Оттуда же удалено предупреждение о массовом сносе контейнеров: ту же форму
  теперь перехватывает отказ.

Проверки: 3037 юнитов, 18 живых на трёх машинах лаборатории, мутации по новому коду 79–88 %.
Остаток мутантов — текст сообщений и разбор кавычек, где поломка лишает удар пробы, но не
пропускает его.

## Что опровергла живая проверка

| Предполагалось | Оказалось |
|---|---|
| признаки жизни берём `ss` | `ss` нет ни на одной машине лаборатории — читаем `/proc` |
| возраст процесса даёт `ps -o etime` | на BusyBox таких ключей нет — считаем из `/proc` |
| проба безопасна, она ничего не меняет | проба по строке находит саму себя |
| маркер можно дописать к любой команде | маркер-комментарий уезжал в аргументы и портил пробу |
| образец в подтверждении равносилен номеру | образец снимает собственную оболочку раньше цели |

Последнее оказалось важнее прочего и попало в [ADR-014](../../decisions/014-blind-target-is-shown-not-guessed.md)
отдельным решением: поиск по командной строке не подтверждается, а переписывается — по
номерам либо прикрытым образцом.

## Критерий готовности

Та самая строка из разбора — три удара по неназванным целям, склеенные с диагностикой, —
не выполняется, а возвращает список того, что попало бы под удар, с именами и признаками
жизни. Повторная отправка той же строки не проходит. Прогон подтверждён на обоих
контейнерах, мутации по новому коду без выживших.
