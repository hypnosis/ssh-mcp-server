## Зачем этот спринт

В проекте живут два способа ходить по SSH: библиотека `ssh2` и системный `ssh`. Второй
проверен живьём и умеет всё, что умеет первый. Пока их двое, каждая правка делается дважды,
а каждый тест доказывает поведение только одной половины.

Спринт оставляет один транспорт и убирает следы второго.

**Точка невозврата — снос `ssh2`.** После него вернуться можно только откатом коммита,
поэтому порядок работ такой: сначала переключить дефолт и убедиться, что всё живо, и
только потом удалять.

**Рамка сверх этого.** Сервер должен ходить не только на свежую Ubuntu, но и на роутер, где
половина протоколов не собрана. Поэтому поддержка старых серверов живёт **слоем, а не ветками
`if` по коду**. Основа уже есть: `runtime-check.ts` знает, что умеет клиент, `passport.ts` —
что умеет сервер, `ssh-args.ts` выбирает способ подготовки пути по режиму клиента. Всё новое
ложится туда же.

---

## Решения, принятые до старта

- **Дверь к транспорту остаётся.** `get-runner.ts` не удаляем: логики в нём после сноса нет,
  но это единственная точка, где инструменты берут соединение. Когда появится слой для старых
  серверов, развилка встанет туда, а не в четыре инструмента.
- **На выходе соединения не закрываем.** Сокет общий для машины: закрытие рвало бы канал
  соседнему окну и стоило бы полного входа при каждом перезапуске. Но оставленное показываем
  и срок простоя называем — см. 2.3.
- **Срок простоя задаётся переменной окружения, не параметром вызова.** Срок прибивается к
  соединению в момент подъёма, поэтому число из второго вызова ничего бы не изменило —
  получилось бы обещание, которое некому выполнить.

запускает владелец, мутации по всему тронутому.

## Долги, подтверждённые сверкой, но не взятые в спринт

Каждый проверен по коду. Уходят записью в `docs/tech-debt/` (пункт 1.3).

| Пункт | Где | Цена, если не трогать |
|---|---|---|
| Ни один ответ не несёт `isError` | все инструменты, кроме `monitoring-tool` | клиент не отличает провал от содержимого |
| Частичный вывод убитой команды не читает никто | `errors.ts:65-96` создаётся, в `src/tools/` не читается | вывод до обрыва теряется |
| Поиск следов не проверяет обрезку вывода | `remote-path-ops.ts`, `listArtifacts` | назовём не все артефакты, молча |
| Гонка двух установок: проигравшему уезжает сырой текст `mv` | `installer.ts:188-199` | «cannot stat» вместо объяснения |
| Отмена не доходит до инструментов | `exec-tool.ts`, `transfer-tool.ts` — `signal` нет | длинную операцию нечем прервать |
| `stat -c` без ветки для BSD и macOS | `remote-path-ops.ts:79` | проверка точки монтирования молча «не знает» |

## Границы

- Имена инструментов и формат профилей не меняем — пакет опубликован в npm.
- Отмена уже запущенной команды и частичный вывод убитой команды — не сюда, это отдельная
  работа по SDK.
- Функциональность не сужаем: если что-то работает только на `ssh2`, это повод разобраться,
  а не повод удалить возможность.

## Проверка

- `npx tsc --noEmit` — чисто, включая мёртвые объявления.
- Юниты зелёные целиком; после чанка 2 назвать фактический счёт.
- Живая сетка на обоих контейнерах, а для задачи 4.1 — на всех трёх.
- Мутации по накопленному диффу на границе чанка: выживших в свежем коде нет, либо каждый
  назван с решением (тест / эквивалентный / в `docs/tech-debt/`). Итог читать по строке
  `Tests …`; её отсутствие означает, что прогон не состоялся.
- Живой тест `removal-guard.live` при выключенной врезке сносит лабораторию по-настоящему.
  После такой мутации: `docker rm -f mcp-alpine mcp-debian mcp-router && npm run lab:up`.
- Каждый новый живой тест проверен негативным контролем: сломать ожидание, убедиться, что
  краснеет, вернуть копией файла (не `git checkout` — им сносятся соседние правки).
