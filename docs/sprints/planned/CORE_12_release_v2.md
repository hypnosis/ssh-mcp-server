**Ветка:** `feat/openssh-transport`
**Предшественники:** CORE_10 (смоук на боевых пройден дважды), CORE_11 (ревью ветки пройдено)

## Зачем этот спринт

Код готов, документация описывает проект, которого больше нет. Спринт приводит написанное
к факту и выпускает мажорную версию.

Мажорная — потому что меняется требование к машине пользователя: своего SSH в пакете
больше нет, нужен системный клиент. Молча такое не выпускают.

Порог не один, и это уточнено по коду (`src/runner/runtime-check.ts`): 5.6 — общее
мультиплексированное соединение, 8.4 — парольные профили и ключи с паролем, 9.0 — `scp`
поверх SFTP. Формулировка «не ниже 8.4» сужала: на ключевых профилях работает и более
старый клиент.

## 📊 ЗАДАЧИ

### 1. Агентная вычитка README

**Что не так.** 1136 строк, из них около 400 — примеры вызовов инструмента за
инструментом. README перестал быть витриной и стал справочником, который никто не
дочитывает. Читателю нужно за один экран понять, что это, что нужно машине и как
запустить; всё остальное — в `docs/`.

**Целевой размер: 250–350 строк.** Не самоцель, а следствие: витрина, ссылки, ничего
дублирующего `docs/`.

**Почему агентами.** Сверять 1136 строк с кодом в одном контексте — работа, где к
середине забывается начало. Нарезка по разделам даёт каждому агенту обозримый кусок и
проверяемый ответ.

**Волна 1 — чтение, пять агентов параллельно.** Каждому свой диапазон строк:

| # | Диапазон | Разделы |
|---|---|---|
| 1 | 12–175 | Features, Installation, Quick Start, профили, Path Security |
| 2 | 176–436 | `ssh_exec`, detach-джобы, `ssh_file_read`, `ssh_file_write` |
| 3 | 437–671 | `ssh_log_*`, `ssh_snapshot`, `ssh_monitor`, Transfer tools |
| 4 | 672–832 | Audit tools, рекомендованный конвейер, Environment Variables |
| 5 | 833–1136 | Оба раздела Security, Architecture, Development, Roadmap, Contributing |

**Агент ничего не правит.** Возвращает отчёт из трёх списков:

- **Расхождение** — утверждение против кода, с доказательством `file:line`. Без
  доказательства пункт не принимается.
- **На вынос** — что справочник, а не витрина, и в какой файл `docs/` это переезжает.
- **Сомнительное** — утверждение о поведении на сервере, которое ни кодом, ни тестом не
  подтверждается. Проверяется замером на лаборатории, а не правится по памяти.

Ответ «расхождений нет» — нормальный ответ, и он должен быть разрешён в промпте явно.

**Волна 2 — правка.** README переписывается целиком одним заходом по собранным отчётам:
пять агентов в один файл писать не могут, а последовательная правка чужого текста
превращается в редактуру редактуры. Вынесенное уезжает в `docs/` — новым файлом
`docs/tools.md` либо в существующие `transfer.md` и `audit.md`, по принадлежности.

**Проверка задачи:** README открывается и читается за один экран до слов «как запустить»;
ни одно утверждение о поведении на сервере не осталось неподтверждённым; `docs/` не
потерял ни одного вынесенного примера.

### 4. CHANGELOG: миграционная секция

Мажорная версия требует прямого разговора с тем, кто обновляется:

- системный `ssh` на `PATH` обязателен, своего в пакете нет;
- три порога версии клиента (5.6 / 8.4 / 9.0) и что именно даёт каждый;
- проверка ключа хоста включена;
- совет остаться на `1.x` тем, кого это не устраивает;
- два ограничения, с которыми выходим:
  [TD-08](../../tech-debt/cancellation-not-wired_08.md) — отмена освобождает нашу сторону,
  но не снимает команду на сервере; [TD-09](../../tech-debt/mountpoint-check-bsd_09.md) —
  проверка точки монтирования знает синтаксис GNU и BusyBox.

Изменения поведения из CORE_09 и CORE_10 собраны в разделе тех спринтов «Изменения
поведения для миграционной секции» — оттуда и берутся, а не сочиняются заново.

- `npm pack`, установка получившегося архива в чистый каталог, один живой вызов

  репозитория: она смотрит на то, что реально уедет в реестр.
- Дальше **стоп**. `npm publish` и git tag необратимы — версию из реестра не отзывают.
  Решение и руки владельца.

## Границы

- Имена инструментов и формат профилей не меняем — пакет опубликован в npm.
- Документация правится **после** живой проверки поведения, а не по памяти о том, как
  задумывалось.
- Работающую функциональность не сужаем ради краткости README: сокращается текст, а не
  возможности.
- Боевые серверы в проверках не участвуют — только лаборатория.

## Проверка

- Каждое утверждение в README и `docs/` про поведение на сервере подтверждено тестом или
  замером на контейнерах.
- Юниты и живая сетка зелёные перед публикацией.
- Пакет установлен в чистый каталог и ответил на живой вызов.

```
Установленные факты, чтобы ты их не достраивал:
- CORE_10 (смоук инструментов на боевых) пройден дважды, CORE_11 (ревью ветки) пройдено.
  Открытых спринтов, кроме этого, нет. CORE_14 (интерактивный режим) к релизу не привязан.
- Бэкенд ssh2 снесён полностью, пула соединений нет. Транспорт один — системный ssh
  с ControlMaster.
- Сторож опасных команд переписан в FIX_17: две ступени (предупреждение и отказ),
  порог и его границы описаны в docs/decisions/007-refusal-threshold.md. Раздел
  README «Security» на строке 833 свежий, его переписывать не надо — а вот второй
  раздел «Security» на строке 1065 с ним соседствует, и это дубль.
- Версия в package.json 1.3.2, целевая 2.0.0. Пакет опубликован в npm: имена
  инструментов и формат профилей не ломаем.

  сервере) и TD-09 (проверка точки монтирования знает GNU и BusyBox). Их не чинить,
  только сверить формулировки.

Порядок работ задан спринтом: README → ROADMAP → BUGLIST → CHANGELOG → версия и
прогоны → проба публикации. README первым, потому что он задаёт формулировки, которые
потом отражаются в остальных файлах.

Задача 1 (вычитка README) идёт агентами, пятью параллельно, по диапазонам строк из
спринта. В промпт каждому агенту клади:
- его диапазон и требование доказывать каждое расхождение ссылкой file:line;
- запрет что-либо править — агент возвращает отчёт, правит основной контекст;
- разрешение ответить «расхождений нет» — без этого агент найдёт себе работу;
- правило разведки: сначала mcp__lumen__semantic_search («где живёт логика X»),
  потом grep по точному имени, потом чтение файла. Агент не видит ни CLAUDE.md,
  ни хуков — без этого пойдёт грепать дерево вслепую.

Правила проекта, которые здесь действуют (docs — не исключение):
- утверждение о поведении на сервере подтверждается замером на лаборатории
  (npm run lab:up, контейнеры mcp-alpine:2231 и mcp-debian:2232), а не рассуждением;
- проверено на одном контейнере — значит не проверено;
- боевые серверы в проверках не участвуют.

Публикацию в npm и git tag не делать. Довести до состояния «готово к публикации»,
показать, что проверено, и остановиться — решение владельца.

Начни с ASK: прочитай спринт, предъяви понимание и план, дождись подтверждения.
Кода и правок до подтверждения не делать.
```
