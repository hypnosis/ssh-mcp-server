# TD-04. Косметика вывода аудита

**Дата:** 2026-08-05
**Статус:** ✅ закрыт 2026-08-14
**Откуда:** смоук 14 инструментов на лаборатории (CORE_10, задача 8)

---

Смоук нашёл три дефекта честности ответа — они закрыты в том же заходе
(`ssh_tls_check` больше не выносит приговор непрочитанному сертификату, раздел
диска перестал молчать на BusyBox, отсутствие `ss`/`netstat` помечается как
непроверенное). Здесь оставалось то, что смотрится плохо, но данных не искажает.

## `ssh_disk_breakdown` показывал служебные разделители

Человеческая часть ответа шла вместе с внутренними метками:

```
=== ssh_disk_breakdown ===
__SSH_MCP_DISK_SEP__df__SSH_MCP_DISK_SEP__
Filesystem  Type  Size  Used ...
```

## `ssh_service_status` клал текст ошибки в поле значения

На сервере без systemd ответ выглядел так:

```
enabled: sh: systemctl: not found
active:  ?/?
```

Читалось человеком верно, но формально это то же смешение, что чинилось в
baseline: «команды нет» подавалось как значение поля.

## Что сделано

Оба пункта закрыты попутно, коммитом `42bc427` (тот же заход, что и TD-15):
вывод режется по меткам тем же `splitSections`, что и у остальных инструментов
аудита, секции получают человеческие заголовки, а место запрошенного пути в
заголовке занимает сам путь, а не номер секции. У службы три исхода различены:
systemd не ответил — все три графы `NOT CHECKED`, юнита нет — `no unit by that
name`, служба живая — прежнее значение.

Запись оставалась открытой по недосмотру: код изменился, реестр — нет.

## Чем доказано

Замер живьём через harness приёмки, семь вызовов на трёх стендах (`td04.json`):

- `ssh_disk_breakdown` на debian, alpine и router, в том числе с двумя путями
  сразу: служебных меток в ответе ноль, заголовки — `--- filesystems ---`,
  `--- largest entries under / ---`, `--- largest entries under /var ---`,
  `--- docker ---`, `--- journald ---`, `--- /var/log ---`, `--- $HOME/.cache ---`;
- `ssh_service_status` на тех же трёх стендах (systemd нет ни на одном): все три
  графы `NOT CHECKED`, сырая строка `sh: systemctl: not found` остаётся только в
  разделе `--- status ---`, где она и есть сырой вывод.

Сторожа — юниты `audit-tls-service.test.ts`: метки не доезжают до ответа, путь в
заголовке назван для каждого из двух запрошенных, `NO_DOCKER` читается как
`not installed`, отсутствие systemd помечено.

Ветка «systemd есть, юнита нет» живого стенда не имеет — в лаборатории systemd
нет ни на одном контейнере; она покрыта юнитом и в этом заходе не менялась.
