# TD-02. CI собран на устаревших версиях чужих блоков

**Дата:** 2026-08-05
**Статус:** ✅ закрыт в тот же день, коммит `f88b301`
**Откуда:** предупреждение в первом прогоне CI на ветке `feat/openssh-transport`

---

## Что происходит

`.github/workflows/test.yml` использует `actions/checkout@v4` и
`actions/setup-node@v4`. Это чужие готовые блоки: первый выкачивает репозиторий,
второй ставит Node. К версии Node самого проекта отношения не имеют.

Внутри они собраны под Node 20, который GitHub признал устаревшим. Прогон от
этого не падает — GitHub запускает их принудительно на Node 24 и печатает
предупреждение:

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are
being forced to run on Node.js 24: actions/checkout@v4, actions/setup-node@v4
```

## Насколько отстали

| Блок | У нас | Актуальная | Вышла |
|------|-------|-----------|-------|
| `actions/checkout` | v4 | v7.0.1 | 2026-07-20 |
| `actions/setup-node` | v4 | v7.0.0 | 2026-07-14 |

Три мажорные версии.

## Чем закончилось

Обновили до v7 отдельным коммитом — не заодно с чужой правкой, потому что
мажорная версия меняет поведение. Сначала проверили каждое ломающее изменение
против этого воркфлоу:

- `setup-node@v5` включает автокэш при поле `packageManager` в `package.json` —
  поля нет, значит не сработает;
- `setup-node@v6` сужает автокэш до npm — нас не касается по той же причине;
- `checkout@v7` блокирует checkout форкового PR при `pull_request_target` и
  `workflow_run` — таких триггеров в репозитории нет;
- `v5` требует runner не ниже v2.327.1 — на `ubuntu-latest` у GitHub он всегда
  свежее.

Замер на живом прогоне:

```
до  (v4): Node.js 20 is deprecated… actions/checkout@v4, actions/setup-node@v4
после (v7): ни одной аннотации, job зелёный, 35 с против 42 с
```

**Осталось за рамками.** `node-version: '20'` в воркфлоу — это уже про Node
самого проекта, а не про чужие блоки. Не трогали, решается отдельно.
