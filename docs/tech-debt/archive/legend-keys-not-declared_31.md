# TD-31. Легенда ответа объявлена, но правило её ключей нигде не сказано

**Дата:** 2026-08-21
**Статус:** ✅ закрыт 2026-08-21 — форма ключа названа в схеме, её видят все восемь инструментов
**Откуда:** круг проб на трёх чистых агентах, общий разбор поверхности

---

## Что происходит

`legend` объявлена почти в каждой схеме ответа и выглядит в поверхности так
(`src/tools/legend.ts`):

```ts
export const LEGEND_SCHEMA: OutputSchema = {
  type: 'object',
  additionalProperties: { type: 'string' },
};
```

Ни описания, ни примера ключа. Между тем ключи строятся по правилу: имя поля, знак
равенства, значение — `state=limited`, `jobs[].state=lost`. Правило живёт в `legendFor`
и в комментарии над ним, то есть в коде, а не в поверхности.

## Что показал прогон

Агент назвал это прямо: поле встречается в большинстве схем, но по одной поверхности
непонятно, какие термины оно объясняет, — узнаётся только по факту первого настоящего
ответа. Инструкция сервера обещает, что «its legend explains the words it uses», и на этом
обещании всё заканчивается: читатель не знает ни формы ключа, ни того, что в легенду
попадают только встретившиеся значения, а не весь словарь схемы.

## Чем чинится

Одной строкой `description` в `LEGEND_SCHEMA`: назвать форму ключа, дать один пример и
сказать, что объясняются только значения, которые в этом ответе действительно были.
Правка в одном месте расходится на все инструменты, объявляющие схему.

Цена — десятки знаков на инструмент, и они повторяются в каждой схеме. Если это окажется
дорого, второй вариант — сказать правило один раз в инструкции сервера, где легенда уже
упомянута, и не трогать схемы вовсе.

## Чем закрыто

`description` у `LEGEND_SCHEMA` (`src/tools/legend.ts:42`): что означают слова ответа, форма
ключа с двумя примерами и граница — объясняются только встретившиеся значения. Объект схемы
один на всех, поэтому строка разошлась по восьми инструментам без правки в каждом.

**Живая проверка.** Собранный сервер запущен и спрошен `tools/list` настоящим протоколом:
из восемнадцати инструментов легенду объявляют восемь (`ssh_exec`, `ssh_file_write`,
`ssh_job_kill`, `ssh_job_list`, `ssh_job_status`, `ssh_monitor`, `ssh_upload`,
`ssh_download`), и текст у всех восьми один и тот же.

**Сторож.** `tests/unit/mcp-contract.test.ts` — все восемь имён поимённо, проверяются обе
половины строки. Мутация: без описания шесть тестов краснеют, `npm run mutate -- HEAD`
убивает все шестнадцать мутантов файла. Первая редакция теста оставила одного живым —
сторожилась только вторая половина склеенной строки.
