## Что это за список

Мутационный прогон по двенадцати файлам последнего коммита. Балл не смотрим — смотрим на
выживших **в строках, которые тронул этот коммит**: 89 строк в `log-tools.ts`, 56 в
`audit-tool.ts`, 21 в `output-notes.ts`.

Каждый пункт ниже перепроверен руками: мутация вносится, гоняется тест, мутация
откатывается. Это важно, потому что отчёт Stryker в этом прогоне врал в обе стороны — см.
последний раздел.

Все они означают одно: **тест недописан**, а не «код сломан». Код делает верно, но если
завтра кто-то сломает эту строку, ни один тест не покраснеет.

намеренно переписываем каждый спринт, и дословный тест на них — обслуживание ради балла.

## Отдельно: отчёт мутаций врал

Часть мутантов помечена `Survived`, хотя тесты их убивают. Проверено руками на четырёх:
`audit-tool.ts:1060` (предикат заменён на `line`), `audit-tool.ts:1068`,
`log-tools.ts:553`, `log-tools.ts:986` — каждый роняет тест, если внести его вручную.

Догадка была на анализ покрытия: Stryker сопоставляет мутанту набор покрывающих тестов, а
наши юниты поднимают модуль через `await import(...)` на верхнем уровне и подменяют
зависимости `vi.mock`. Если сопоставление не срабатывает, мутант объявляется выжившим, не
запустив ни одного теста.

### Замер догадку опроверг

Двенадцать файлов коммита прогнаны дважды подряд, одна и та же версия кода: обычным
`perTest` и с `--coverageAnalysis off`. Списки выживших сверены по позиции и мутатору.

| | perTest | off |
|---|---|---|
| всего | 5059 | 5059 |
| убито | 3909 | 3909 |
| выжило | 1048 | 1048 |
| не покрыто | 93 | 93 |

Выжил в одном и умер в другом — ноль в обе стороны. Анализ покрытия исправен, менять
`stryker.conf.json` не на что.

Значит расхождение с ручной проверкой объясняется самой ручной проверкой: вносилась не та
правка, что делает мутант. Остаётся правило, которое от этого только крепче:

- **Список выживших нельзя брать как есть.** Каждый пункт проверяется руками, и мутация
  вносится дословно по полю `replacement` из JSON, а не по смыслу строки.
- Построчный список выживших отчёт даёт только с json-репортером: в конфиге его нет,
  задавать в командной строке — `--reporters json,progress`.

## Как проверять починку

Каждая дописанная проверка проверяется мутацией: внести мутацию из таблицы, убедиться, что
тест красный, откатить копией файла (не `git checkout` — им сносятся соседние правки).
