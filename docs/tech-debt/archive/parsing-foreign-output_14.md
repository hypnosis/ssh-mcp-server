# TD-14. Разбор чужого вывода теряет строки и путает колонки

**Дата:** 2026-08-13
**Статус:** ✅ закрыт 2026-08-14
**Откуда:** приёмка, находки AC-13, AC-26, AC-27, AC-28

---

Четыре места, где вывод системной утилиты разбирался по счёту колонок или по позиции
разделителя. Пока формат совпадал с ожидаемым, всё было верно; как только сервер печатал
иначе — строка молча пропадала или вставала не в ту графу.

## Корня не было в обзоре дисков

`ssh_snapshot` брал строки из `df -h | grep -E "^/dev/"`. В контейнере корень лежит на
overlay, под этот отбор он не подходит и в список не попадал вовсе, зато попадали файлы,
подмонтированные внутрь. На всех трёх стендах обзор выглядел так:

```
Disk:
  /etc/resolv.conf 5.7G     / 487.1G   (1%)
  /etc/hostname 5.7G     / 487.1G   (1%)
  /etc/hosts 5.7G     / 487.1G   (1%)
```

**Стало:** снимок читает `df -hT`, отбрасывает служебные системы ядра по типу (тот же
список, что у аудита) и показывает одну строку на устройство — с самой короткой точкой
монтирования. Тот же стенд после правки:

```
Disk:
  /          5.7G     / 487.1G   (1%)
  /tmp/authkey 992.6G   / 1.8T     (53%)
  /etc/hosts 5.7G     / 487.1G   (1%)
```

Строку, которую разобрать не вышло, снимок печатает как `NOT CHECKED: df printed a row in
an unexpected shape: …`, аудит — тем же текстом в списке «нечем проверить». Раньше она
исчезала бесследно.

## Перенос длинного имени тома терял имя, а не строку

Запись долга утверждала, что обе половины перенесённой строки отбрасываются условием
`cols.length < 7`. Замер на стенде с подложенной `df` показал другое: вторая половина
выровнена пробелами, при разбиении по пробелам получалось пустое первое поле — ровно на
место пропавшего имени. Строка доезжала, но с пустым `filesystem`:

```
{ "fs": "", "mount": "/mnt/media", "used": "1.7T", "size": "2.0T", "pct": "85%" }
```

**Стало:** одинокое первое поле склеивается со следующей строкой, и имя тома на месте
(`nfs-storage.internal.example.com:/export/media/library`).

## Кэш под именем «доступно»

`available` бралось как последняя колонка строки `Mem:`. У `free` из procps старше
примерно 2014 года такой колонки нет, и последней идёт `cached`: на подложенном выводе
инструмент объявлял 3.4G доступной памяти при 800M свободной.

**Стало:** показатели читаются по именам колонок заголовка. Нет колонки — `avail=n/a`.
Вывод вообще без заголовка разбирается по прежнему порядку, но `available` в нём места не
имеет и тоже отвечает `n/a`.

## Слушатель только на IPv6

Порт вырезался из адреса через `cut -d: -f2`: для `0.0.0.0:443` это работало, для `[::]:4847`
второе поле пусто и запись отсеивалась. На стенде со вторым sshd на `:::4847` прежний
конвейер отдавал пустую строку, инструмент — список из одного порта 22.

**Стало:** порт берётся после последнего двоеточия, а совпадающие порты IPv4 и IPv6
схлопываются в одну строку. Тот же стенд после правки печатает `4847 unknown` рядом с 22.
У `ssh_audit_baseline` этого дефекта не было: он разбирает адрес целиком.

## Чем проверено

Живьём на alpine, debian, router и боевом сервере — тот же замер до и после. Случаи,
которых в лаборатории нет, воспроизведены стендом: на debian подложены `df` с переносом
строки и `free` без колонки `available`, на alpine поднят второй sshd, слушающий только
IPv6. Стенд убран, контейнеры проверены. Юниты: 1475 зелёных, из них новые — разбор
переноса, отбор по типу, дедуп по устройству, неразобранная строка в обоих инструментах,
две колонки памяти и два случая с IPv6. Каждая правка проверена мутацией: ломаешь — тест
краснеет.
