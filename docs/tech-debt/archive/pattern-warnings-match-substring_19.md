# TD-19. Предупреждения ловят слово, а не команду

**Дата:** 2026-08-16
**Статус:** 📌 открыт
**Откуда:** боевая раскатка на finlab, приёмка 04

---

Аудит свежего сервера печатает:

```
⚠️  DANGEROUS COMMAND: reboot detected
Command: test -f /var/run/reboot-required && cat /var/run/reboot-required
```

Ничего не выполнялось и не перезагружалось — читался файл. Слово `reboot` встретилось
в его имени, а шаблон `/\breboot\b/` (`src/tools/exec-tool.ts:40`) границами слова от этого
не защищён: слева слэш, справа дефис.

## Почему это уже решённый вопрос, вернувшийся с другой стороны

Прямо над списком, в `exec-tool.ts:28-34`, написано, почему из него убрали удаление:
шаблон срабатывал на любом абсолютном пути и кричал даже на `echo "rm -rf /"`.
Вывод там же: предупреждение, которое звучит на штатной работе, агент перестаёт читать,
и настоящая беда теряется в шуме. Решение — разбор пути в `destructive-command.ts`
вместо поиска подстроки.

Для удаления это сделано. Остальной список остался прежним и болеет тем же:

| Шаблон | На чём сработает зря |
|---|---|
| `\breboot\b` | `/var/run/reboot-required` — файл, который читает любой аудит |
| `\bhalt\b` | пути и слова, содержащие `halt` |
| `\bTRUNCATE\b/i` | слово в тексте, комментарии, названии |
| `\bshutdown\b` | упоминание в строке, а не вызов |

Отдельная неловкость: файл `/var/run/reboot-required` читает и собственный аудит проекта
(`audit-tool.ts:260`), то есть шаблон ругается на действие, которое инструменты делают сами
и постоянно.

## Что сделать

Проверять не текст, а команду: имя исполняемого файла в позиции команды. `reboot` как
первое слово простой команды — это вызов; `reboot` внутри аргумента, пути или строки в
кавычках — не вызов. Разбор у проекта уже есть, он написан для сторожа удаления.

Порог решает не строгость, а доверие к сигналу: предупреждение должно значить, что команда
действительно перезагрузит машину. Пока это не так, строку читают как фон — ровно то,
против чего написан ADR-0003.

## Чем проверять

Пара «вызов» и «упоминание» — два теста на каждый шаблон, не один:

- `reboot` и `shutdown -r +1` — предупреждение обязано быть;
- `test -f /var/run/reboot-required`, `grep reboot /var/log/syslog`, `echo halt` —
  предупреждения быть не должно.

Живая проверка не нужна: разбор идёт до отправки, стенд ничего не добавит.

## Как закрыто

Спринт [FIX_16](../sprints/planned/FIX_16_audit_speaks_to_the_point.md), задача 5.

Разбор команды вынесен в `src/utils/command-parse.ts` — тот самый, что был написан для
сторожа удаления; второй не заводился. Проверяется имя в позиции команды, а запросы к БД
ищутся только там, где вызван клиент базы.

**Замер «после»**, свежая сборка против alpine:

```
   тихо  test -f /var/run/reboot-required && cat /var/run/reboot-required
   тихо  grep reboot /etc/hostname
   тихо  echo halt
   тихо  git commit -m "fix; reboot handler" || true
⚠️  ПРЕДУПРЕДИЛ  docker system prune -a
⚠️  ПРЕДУПРЕДИЛ  psql -c "TRUNCATE users;"
⚠️  ПРЕДУПРЕДИЛ  chmod 777 /tmp/fix16-probe
⚠️  ПРЕДУПРЕДИЛ  timeout 5 poweroff
   тихо  docker image prune -a
```

По ходу вскрылись две вещи, которых в долге не было:

- точка с запятой внутри кавычек начинала новую команду, и `git commit -m "fix; reboot
  handler"` давал вызов `reboot` — ложная тревога в новой форме. Разделители теперь режут
  только вне кавычек;
- обёртки (`timeout 5 …`, `nice -n 10 …`, `env VAR=1 …`) прятали настоящую команду.
  Старый поиск подстроки их ловил, разбор по первому слову — нет. Обёртки пропускаются
  вместе со своими аргументами, охват не сузился.

**Известная граница:** `sudo -u deploy reboot` не распознаётся — значение флага обёртки
неотличимо от имени команды. Для остановки машины форма бессмысленная (нужен root).
