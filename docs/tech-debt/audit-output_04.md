Смоук нашёл три дефекта честности ответа — они закрыты в том же заходе
(`ssh_tls_check` больше не выносит приговор непрочитанному сертификату, раздел
диска перестал молчать на BusyBox, отсутствие `ss`/`netstat` помечается как
непроверенное). Здесь остаётся то, что смотрится плохо, но данных не искажает.

## `ssh_disk_breakdown` показывает служебные разделители

Человеческая часть ответа идёт вместе с внутренними метками:

```
=== ssh_disk_breakdown ===
__SSH_MCP_DISK_SEP__df__SSH_MCP_DISK_SEP__
Filesystem  Type  Size  Used ...
```

Остальные инструменты аудита режут вывод по таким же меткам и наружу их не
показывают. Здесь разбор не сделан вовсе: секции склеиваются как есть.
Чинится вместе с любой следующей правкой этого инструмента — отдельного захода
не стоит.

## `ssh_service_status` кладёт текст ошибки в поле значения

На сервере без systemd ответ выглядит так:

```
enabled: sh: systemctl: not found
active:  ?/?
```

Читается человеком верно, но формально это то же смешение, что чинилось в
baseline: «команды нет» подаётся как значение поля. Разница в цене — здесь
ошибка видна прямо в строке и никого не уводит в неверное действие, поэтому
отдельная пометка «нечем проверить» отложена.
