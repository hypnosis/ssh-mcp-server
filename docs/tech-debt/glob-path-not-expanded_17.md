# TD-17. Шаблон пути в журнальных инструментах обещан, но не работает

**Дата:** 2026-08-14
**Статус:** 🟡 открыт
**Откуда:** замер при закрытии [TD-13](archive/limits-time-and-volume_13.md)

---

Схема `ssh_log_search` обещает шаблон прямо в описании поля: `Log file path, glob pattern
(*.log), or array of paths` (`src/tools/log-tools.ts:86`). На деле путь уезжает на сервер в
одинарных кавычках (`buildSafePath`, `src/tools/log-tools.ts:393-406`), оболочка его не
раскрывает, и утилита отвечает отказом:

```
ssh_log_search  /tmp/globtest/*.log  →  Error: Failed to search log:
                                        grep: /tmp/globtest/*.log: No such file or directory
ssh_log_tail    /tmp/globtest/*.log  →  Error: Failed to read log:
                                        tail: cannot open '/tmp/globtest/*.log' …
```

Точный путь к тому же файлу отвечает нормально, а `ssh_file_list` с полем `pattern`
шаблон отрабатывает — там он разбирается отдельно, не через оболочку сервера.

Замерено на debian с двумя файлами `a.log` и `b.log`; следы убраны.

## Откуда взялось

Тот же класс, что чинили при смене транспорта: раньше путь разбирал протокол, теперь его
разбирает оболочка сервера, и кавычки, спасающие имена с пробелом, `$(...)` и переводом
строки, заодно убивают `*`. Разница в том, что здесь пострадала обещанная возможность, а не
безопасность.

## Что сделать

Решить, что из двух:

- раскрывать шаблон самим — списком файлов, как это делает `ssh_file_list`, и дальше идти
  обычным путём с кавычками на каждом имени;
- либо убрать обещание из описания поля и отвечать понятным отказом, а не сообщением
  утилиты.

Первое возвращает возможность, второе честнее описывает нынешнее поведение. Молчаливое
«не работает, хотя написано» хуже обоих.

## Почему не сделано сразу

Найдено попутно, к границам TD-13 отношения не имеет. Правка задевает разбор пути у обоих
журнальных инструментов, а этот разбор — общий с правилами профиля, так что менять его
между делом не стоит.
