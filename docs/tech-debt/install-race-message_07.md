# TD-07. Проигравший в гонке установок получает сырой текст `mv`

**Дата:** 2026-08-05
**Статус:** 🟡 открыт, не чиним
**Откуда:** CORE_10, список потенциальных багов (замер живьём); проверено по коду в CORE_11, задача 1.3

---

Две установки в один путь одновременно замерены: одна коммитит, вторая отказывает, оба
дерева целы. Сохранность не нарушена — плохо другое.

Отказ уезжает наверх текстом самой утилиты: `installer.ts:163` и `:168` бросают
`committed.error.message`, то есть строку вида `mv: cannot stat …`. Из неё не понять, что
произошло на самом деле: в этот путь одновременно писал кто-то ещё, и ничего не изменено.

## Что сделать

Назвать причину словами вызывающего, а не словами `mv`. Замок через `mkdir` возможен и
проверен, но добавляет состояние, которое надо снимать после аварий, — поэтому решение
не сводится к одной строке и требует отдельного разбора.

## Почему не сделано сразу

Данные целы в обоих исходах, страдает только понятность ответа. Гонка двух установок в
один путь — редкий сценарий; правка ждёт работы над честностью ответов инструментов,
где меняется формат ошибок целиком — [TD-03](tool-schemas_03.md).
