# TD-15. В ответах видно внутреннюю кухню: временные имена и служебные метки

**Дата:** 2026-08-13
**Статус:** 🟡 открыт, в v2.1
**Откуда:** приёмка, находки AC-06, AC-08, AC-16, AC-17, AC-29, AC-30

---

Инструмент показывает пользователю то, о чём тот не спрашивал: путь временного файла,
разделитель, которым внутри режется вывод, сырое исключение Node.

**Временное имя вместо запрошенного пути.** Запись `/etc/denied-probe.conf` без прав
отвечает так:

```
Error: Command failed (exit 1): cat > '/etc/.upload-7952b8939bc0.denied-probe.conf'
— bash: line 1: … Permission denied
```

Пользователь называл другой путь. То же у `ssh_upload` при неудачном `chown`
(`chown nosuchuser -- '/tmp/xfer/.upload-d28717bc983e.owner-sudo.txt'`). Источник общий —
команда подставляется в текст ошибки как есть (`src/managers/ssh-executor.ts:136-141`),
а мест, где в команде стоит временное имя, несколько: `mv -T`
(`src/managers/remote-path-ops.ts:93-99`), `cp` под sudo и `chmod`/`chown`
(`src/tools/transfer-tool.ts:472-476,498-510`).

**Сырое исключение Node.** Отсутствие локального файла у `ssh_upload`:
`Error: ENOENT: no such file or directory, stat '/…/no-such.txt'`. Отказ локального
переименования у `ssh_download` (`src/managers/local-path-ops.ts:56-58`) отдаёт `EACCES`
вместе с временным именем — причём уже после того, как файл скачан: данные на месте, а
сообщение выглядит как поломка.

**Служебные разделители.** Ответ `ssh_disk_breakdown` начинается с
`__SSH_MCP_DISK_SEP__df__SSH_MCP_DISK_SEP__` и содержит такую же метку перед каждым
блоком. Данные верные, показан способ их нарезать.

**Сырые сообщения systemctl в полях отчёта.** `ssh_service_status` для несуществующей
службы печатает в графе `enabled` текст ошибки:
`Failed to get unit file state for no-such-unit.service: No such file or directory`, а
ниже спокойно продолжает `active: inactive/dead`. На стенде без systemd — `enabled:
enabled` рядом с `active: ?/?` и «System has not been booted with systemd as init
system»: часть полей заполнена, часть в вопросах, общего «судить нечем» нет.

## Что сделать

Одно место на всё: перед выдачей ошибки наружу подменять внутреннее имя на путь, который
назвал пользователь, а исключения файловой системы переводить в человеческий отказ.
Разделители убрать из вывода, оставив в разборе. Полям `ssh_service_status` — те же три
исхода, что и остальным: значение, «нет», «проверить нечем».

## Почему не сделано сразу

Мелочи по решению о границах релиза: данные верны, поведение верно, страдает только текст
ответа. Правка общая для всех инструментов — её место рядом с введением `isError` в
[TD-03](tool-schemas_03.md), где формат ответа меняется один раз.
