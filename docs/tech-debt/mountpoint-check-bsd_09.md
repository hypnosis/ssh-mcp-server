# TD-09. Проверка точки монтирования не знает BSD и macOS

**Дата:** 2026-08-05
**Статус:** 📌 названное ограничение, ждёт стенда BSD/macOS (пересмотрено 2026-08-19)
**Откуда:** CORE_10, список потенциальных багов; проверено по коду в CORE_11, задача 1.3

---

Установщик отказывается заменять путь, лежащий на отдельной файловой системе: там
переименование превращается в копирование и перестаёт быть атомарным. Отличает такой путь
`isSeparateFilesystem` (`src/managers/remote-path-ops.ts`) — сравнивает номера устройств
командой `stat -c %d`.

`stat -c` — синтаксис GNU и BusyBox. На BSD и macOS нужен `stat -f`, и там команда ничего
не печатает: разбор не получает двух чисел.

## Что сделано

Молчание сервера перестало читаться как «проверено, не точка монтирования». Исходов теперь
три, как и везде в проекте: `separate` — отказ до единого изменения на диске, `same` —
обычная установка, `unknown` — установка идёт, но в ответ уходит пометка, что проверить
было нечем. Работающая функциональность не сужена: проверка и раньше никого не блокировала
сама по себе, страховкой остаётся отказ переименования.

Мусорный ответ отличается от номеров: BusyBox на неизвестный ему спецификатор печатает сам
символ формата и выходит с нулём — две строки, обе не числа. Без проверки на числа такой
ответ сравнивался бы как номера устройств.

## Что осталось ограничением

Ветка под `stat -f` не написана. Серверов BSD и macOS в лаборатории нет, а правка вслепую —
ровно то, что правила проекта запрещают: заявленная функция без живой проверки не сделана.
Появится стенд — способ подбирается по паспорту сервера, как уже сделано для других
расхождений наборов утилит, а не условием в месте вызова.

Пометка «проверить было нечем» — не заглушка на это время, а честный ответ: на таком
сервере проверка действительно не выполняется, и человек читает об этом прямо в ответе.

## Чем доказано

Шим `stat` на debian и alpine, ведущий себя как BSD (опции `-c` не знает), замер через
harness приёмки:

**До:** установка поверх существующего файла отвечает обычным успехом, ни слова о
непроверенном; установка поверх точки монтирования отвечает сырым отказом `mv`.

**После:** оба ответа несут пометку

```
warnings:
  - whether /tmp/mntprobe/app.conf is a mount point could not be checked: the server did
    not answer with device numbers. If it is one, the rename will refuse the replacement
    and nothing will be changed.
```

Шим снят — пометка исчезает, точка монтирования снова распознаётся до записи:
`the target is a mount point: /etc/hosts` на debian и alpine.

Поведение `mv -T` на точке монтирования измерено — раньше отказ был построен на
рассуждении. Точка монтирования, которую не надо создавать: docker кладёт `/etc/hosts`
внутрь контейнера отдельным bind-mount, номер устройства у него свой.

```
coreutils: mv: cannot move '/tmp/newhosts' to '/etc/hosts': Device or resource busy
BusyBox:   mv: can't rename '/tmp/newhosts': Resource busy
```

Оба кода возврата — 1, содержимое цели не изменилось. `rm -rf` по боевому пути установщик
не выполняет вовсе, поэтому его поведение на точке монтирования ни на что не влияет.

Сторожа — юниты `installer.test.ts` («установка идёт, но непроверенное названо
непроверенным», «проверка прошла — про неё ни слова», «цели нет — проверять нечего») и
`remote-path-ops.test.ts` (три исхода плюс ответ не номерами). Проверены мутацией: снятая
пометка и снятая проверка на числа красят по тесту каждая.
